## What is uv?

**uv** is an extremely fast Python package and project manager written in Rust, developed by [Astral](https://astral.sh).

It aims to be a single tool that replaces many others:

| Traditional Tool | uv Equivalent |
|------------------|---------------|
| `pip`            | `uv pip` / `uv add` |
| `pip-tools`      | `uv lock` / `uv sync` |
| `pipx`           | `uvx` / `uv tool` |
| `virtualenv` / `venv` | `uv venv` |
| `pyenv`          | `uv python` |
| `poetry` / `pdm` / `rye` | `uv` project commands |

### Key Features

- **10–100× faster** than pip
- Universal (cross-platform) lockfile (`uv.lock`)
- Manages Python versions
- Project management with lockfiles & workspaces
- Runs scripts with inline dependencies
- Global tool installation (`uvx`)
- Disk-efficient shared cache

### Installation

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# Or via pip / pipx
pip install uv
# or
pipx install uv
```

Update uv itself:

```bash
uv self update
```

## What is pyproject.toml?

`pyproject.toml` is the **standard configuration file** for modern Python projects (defined by PEPs 517, 518, and 621).

It replaces older files such as:

- `setup.py`
- `setup.cfg`
- `requirements.txt` / `requirements.in` (for project metadata)

### Why it matters

- Single source of truth for project metadata and dependencies
- Tool-agnostic (works with uv, Poetry, Hatch, setuptools, Ruff, pytest, etc.)
- Written in TOML (readable and less error-prone than JSON/INI)
- Declares build system, runtime dependencies, optional extras, scripts, and tool configuration

uv **requires** a `pyproject.toml` to identify a project root.

## Project Structure

A typical uv-managed project looks like this:

```
my-project/
├── pyproject.toml      # Project metadata & dependencies (required)
├── uv.lock             # Universal lockfile (generated by uv)
├── .python-version     # Pinned Python version
├── .venv/              # Project virtual environment (managed by uv)
├── README.md
├── src/
│   └── my_project/
│       └── __init__.py
└── tests/
```

### Creating a new project

```bash
uv init my-project
cd my-project
```

This generates a ready-to-use layout including `pyproject.toml`, `.python-version`, and a basic package structure.

Useful variants:

```bash
uv init --app my-app          # Application-style (no package install by default)
uv init --lib my-lib          # Library-style
uv init --bare my-minimal     # Only pyproject.toml
uv init --no-package my-app   # No build system / package
```

## pyproject.toml Sections

### Minimal example

```toml
[project]
name = "example"
version = "0.1.0"
```

### Common full example

```toml
[project]
name = "my-project"
version = "0.1.0"
description = "A short description of the project"
readme = "README.md"
requires-python = ">=3.12"
authors = [
  { name = "Your Name", email = "you@example.com" }
]
dependencies = [
  "httpx>=0.27",
  "pydantic>=2.0",
]

[project.optional-dependencies]
cli = ["rich", "click"]
dev = ["pytest", "ruff"]

[project.scripts]
my-project = "my_project:main"

[dependency-groups]
dev = ["pytest>=8.0", "ruff>=0.6"]
test = ["pytest", "coverage"]

[build-system]
requires = ["uv_build>=0.12.0,<0.13"]
build-backend = "uv_build"

[tool.uv]
# uv-specific configuration goes here

[tool.uv.sources]
# Custom dependency sources (path, git, workspace, etc.)
```

### Section Reference

| Section | Purpose |
|---------|---------|
| `[project]` | Core metadata (name, version, description, authors, requires-python, dependencies) – **PEP 621** |
| `[project.optional-dependencies]` | Extras / optional feature dependencies |
| `[project.scripts]` | Console entry points (CLI commands) |
| `[project.gui-scripts]` | GUI entry points |
| `[dependency-groups]` | Development / non-published groups (test, lint, docs) – **PEP 735** |
| `[build-system]` | Declares the build backend and its requirements |
| `[tool.uv]` | uv-specific settings |
| `[tool.uv.sources]` | Override where packages come from (path, git, workspace, index) |
| `[tool.uv.workspace]` | Workspace members (for multi-package repos) |

## Essential uv Commands

### Project Lifecycle

| Command | Description |
|---------|-------------|
| `uv init [name]` | Create a new project |
| `uv add <package>` | Add a dependency (updates `pyproject.toml`, lockfile, and environment) |
| `uv remove <package>` | Remove a dependency |
| `uv sync` | Install exact versions from the lockfile into `.venv` |
| `uv lock` | Resolve dependencies and update `uv.lock` |
| `uv run <cmd>` | Run a command or script inside the project environment |
| `uv tree` | Show the dependency tree |
| `uv version` | Read or bump the project version |
| `uv build` | Build sdist and wheel |
| `uv publish` | Upload distributions to an index (e.g. PyPI) |

#### Adding dependencies with options

```bash
uv add requests                    # runtime dependency
uv add --dev pytest                # development dependency
uv add --group lint ruff           # named dependency group
uv add --optional cli rich         # optional extra
uv add "httpx>=0.27,<0.28"         # with version constraints
uv add "package @ git+https://..." # from Git
uv add ./local-package             # from local path
```

### Python Version Management

| Command | Description |
|---------|-------------|
| `uv python install 3.12` | Install a Python version |
| `uv python list` | List installed and available versions |
| `uv python pin 3.12` | Pin the project to a specific Python version |
| `uv python find` | Locate a Python interpreter |
| `uv python uninstall 3.11` | Remove a managed Python version |

### Tools (like pipx)

| Command | Description |
|---------|-------------|
| `uvx <tool>` | Run a tool in an ephemeral environment (alias for `uv tool run`) |
| `uv tool install <pkg>` | Install a tool globally |
| `uv tool list` | List installed tools |
| `uv tool uninstall <pkg>` | Remove a global tool |

### Environment & pip-compatible interface

| Command | Description |
|---------|-------------|
| `uv venv` | Create a virtual environment |
| `uv pip install <pkg>` | Install packages (pip-compatible) |
| `uv pip list` | List installed packages |
| `uv pip freeze` | Output installed packages in requirements format |
| `uv pip compile` | Compile requirements (like pip-tools) |
| `uv pip sync` | Sync environment from a requirements file |

### Utilities

| Command | Description |
|---------|-------------|
| `uv cache clean` | Clear the global cache |
| `uv cache size` | Show cache size |
| `uv self update` | Update uv itself |
| `uv help` | Show help for any command |

## Workflow Examples

### 1. Start a new project and add dependencies

```bash
uv init my-app
cd my-app

uv add fastapi uvicorn
uv add --dev pytest ruff

uv run python -c "import fastapi; print(fastapi.__version__)"
```

### 2. Run a script with temporary dependencies

```bash
uv run --with httpx python script.py
```

### 3. Keep the environment in sync

```bash
# After pulling changes that updated pyproject.toml / uv.lock
uv sync

# Upgrade a specific package
uv lock --upgrade-package requests
uv sync
```

### 4. Work with dependency groups

```bash
# Add to a group
uv add --group test pytest coverage

# Sync only specific groups
uv sync --group test
uv sync --all-groups
```

### 5. Export lockfile (e.g. for Docker or other tools)

```bash
uv export --format requirements-txt > requirements.txt
```

## Key Files Explained

| File | Role |
|------|------|
| **`pyproject.toml`** | Human-editable project metadata, dependencies, and tool config. Source of truth. |
| **`uv.lock`** | Machine-generated, universal lockfile. Pins exact versions across platforms and Python versions. Commit this to version control. |
| **`.python-version`** | Pins the default Python version for the project. Used by uv when creating the environment. |
| **`.venv/`** | Project-local virtual environment. Managed automatically by uv — do not edit manually. |

> **Best practice:** Always commit `pyproject.toml` and `uv.lock`. Do **not** commit `.venv/`.
